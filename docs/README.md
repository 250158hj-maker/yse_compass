## 2. ファイルの分け方 — 「更新のされ方」で切っている

**上書きする文書と、追記する文書を、同じファイルに入れない。** これが分割の唯一の根拠。混ざっていると安全に書き換えられず、鮮度が保てなくなる（実際、分割前の1ファイル構成でそうなった）。

| 性質 | 更新のしかた | 該当 |
| --- | --- | --- |
| **いま正しいこと** | 上書き（最新が正） | `requirements.md` / `screens.md` / `glossary.md` |
| **起きたこと** | 追記のみ・過去行を書き換えない | `decisions.md` / `findings.md` |
| **まだ無いこと** | 決着したら `decisions.md` へ移して削除 | `open-questions.md` |
| **人から聞いたこと** | 原文保存・解釈を混ぜない | `hearing.md` |

**新しいファイルを作るときは、この4つのどれかを即答できること。** 即答できなければ、置き場所か切り方が間違っている。

**1行で説明が書けないファイルは作らない。** 説明が書けないということは、そのファイルが何の問いにも答えていないということ。

## 3. 決定が動く道すじ

```
議論・壁打ちで結論が出る
        ↓
docs/decisions.md に1行書く   ← ここで初めて「決定」になる
        ↓
requirements.md / glossary.md / screens.md を書き換える
        ↓
open-questions.md から該当行を削除する
```

**`decisions.md` に1行入るまで、それは決定ではない。** 「決めたのに伝わっていない」という状態を、定義上つくれなくするための規約。

決定を**変更**するときは、過去の行を消さず、新しい行に `【変更】` として書き、旧決定を明記する。
