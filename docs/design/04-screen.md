## この章が答える問い

**要件のどの節が、どの画面のどの部品として現れるのか。** 画面から要件へ逆に辿れることが、この章の完成条件。

## 書くもの

| # | 成果物 | 形式 |
| --- | --- | --- |
| 4-1 | 画面一覧 | 表（画面 ID ／ 名称 ／ URL ／ 主ロール ／ **対応要件** ／ 実装優先度） |
| 4-2 | 画面遷移図 | 図（ロール別。ログイン後の分岐を含む） |
| 4-3 | 画面項目定義 | 画面ごとに：表示項目 ／ 入力項目（型・必須・検証） ／ 操作 ／ 遷移先 |
| 4-4 | 画面別 権限マトリクス | 表（画面 × ロール × 「自チームか否か」） |
| 4-5 | 共通 UI 規約 | 空状態・エラー表示・ローディング・確認ダイアログの方針 |

> **4-1 の「対応要件」列が空の画面を残さない。** 空欄になった画面は、要件の欠落か画面の過剰のどちらかであり、**`open-questions.md` に起票する対象**（`README.md` §3-4）。
